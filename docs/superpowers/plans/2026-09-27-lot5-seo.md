# Lot 5 — SEO et préparation à la mise en ligne — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make PEA Radar ready to be indexed once it is put online: semantic HTML, per-page metadata, robots.txt, sitemap.xml, schema.org JSON-LD, llms.txt, and private pages kept out of search engines.

**Architecture:** The API generates the three text files (`/api/seo/robots.txt`, `/api/seo/sitemap.xml`, `/api/seo/llms.txt`), and nginx and Vite expose them at the site root. Two settings control them: `SEO_INDEXING` (default false, so everything is disallowed locally) and `PUBLIC_BASE_URL`. The frontend has a `src/seo/` module with a `usePageMeta` hook. The hook writes the title, description, canonical, Open Graph, Twitter, robots and JSON-LD tags into `<head>`, and each page calls it.

**Tech Stack:** FastAPI, SQLAlchemy, React 19, react-router 7, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-26-pea-radar-design.md` §10

## Global Constraints

- The UI stays in French and in the light theme. The layout must not be cut off at 1100 px or wider (layout fix at the start of this branch).
- Private pages always get `noindex`: `/portefeuille`, `/assistant`, `/reglages`.
- robots.txt locally or when private (`SEO_INDEXING=false`) is `Disallow: /`. Online, it allows only the public pages: `/`, `/explorer`, `/etf`, `/titres/*`.
- The sitemap lists only public pages: home, explorer, ETF, and pages of active securities with confirmed PEA eligibility (stocks and ETFs, never indices).
- JSON-LD types:
  - `WebApplication` on the home page;
  - `Corporation` with `tickerSymbol` on stock pages;
  - `InvestmentFund` on ETF pages;
  - `BreadcrumbList` on the explorer, ETF and stock pages.
- Exactly one `h1` per page, and no skipped heading level.
- Prerendering is out of scope; it happens when the site goes online.

## Review Focus

1. Going from a public page to a private one, and back, in the SPA: `noindex`, canonical and JSON-LD must follow the current page and never keep the previous page's values.
2. A security name containing `&`, `<` or `</script>`: the sitemap must stay valid XML, and the JSON-LD must not inject HTML.
3. `PUBLIC_BASE_URL` with a trailing `/`: URLs must not contain `//`.
4. An inactive, non-eligible or `index` security must not appear in the sitemap.
5. A page that fails to load or returns 404 (unknown security): no JSON-LD for a missing security, and `noindex`.

### Task 2: Frontend — `usePageMeta`

**Files:**
- Create: `frontend/src/seo/usePageMeta.ts`, `frontend/src/seo/schema.ts`, `frontend/src/seo/usePageMeta.test.tsx`
- Modify: `frontend/index.html` (default description, `og:site_name`, `theme-color`)

**Interfaces:**
- Produces: `usePageMeta({ title, description, path?, noindex?, jsonLd? }: PageMeta)`.
  - `title` is displayed as `${title} | PEA Radar`; the home page passes `null` to show `PEA Radar`.
  - `path` defaults to the current location's pathname.
  - `jsonLd` is an object or an array.
  - The hook manages these tags, each marked `data-seo`:
    - `meta[name=description]`, `link[rel=canonical]`;
    - `og:title`, `og:description`, `og:url`, `og:type`;
    - `twitter:card`, `twitter:title`, `twitter:description`;
    - `meta[name=robots]`, present only when noindex;
    - `script[type="application/ld+json"][data-seo]`.

    On unmount it restores the defaults and removes robots and JSON-LD.
- `schema.ts` exports:
  - `SITE_NAME`;
  - `absoluteUrl(path)`, built on `window.location.origin`;
  - `breadcrumb(items: {name, path}[])`, `webApplication()`;
  - `corporation(detail)`, `investmentFund(detail)`.

  - unmounting removes robots and JSON-LD;
  - `corporation` includes `tickerSymbol` = `"${symbol}"` and `url`; `investmentFund` has the type `InvestmentFund`.
